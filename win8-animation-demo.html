批次 2 · +83ms · 副标题

官方 enterPage 的 staggered entry —— 页面拆成若干区域，各区域分批上屏

批次 3 · +166ms · 说明

批次由 嵌套数组的顶层 决定：enterPage([[标题],[副标题],[说明],[内容]]) → 依次 0 / 83 / 166 / 249 ms。
同一内层数组里的元素才会一起进，例如 [[标题],[副标题],[说明,内容]] → 0 / 83 / 166 / 166 ms。
官方交错量是 min(83 × i, 333) ms；方向默认"从右往左滑"，靠 enterPage 的 offset 参数给水平偏移（官方 SettingsFlyout 用的就是 {left:"±100px"}）。

手势动画

滑动多选与拖拽落点，都是官方给自绘控件准备的手势词汇

① 滑动多选：按住某行向下拖超过 60px 再松开 → swipeSelect；已选中的再拖一次 → swipeDeselect（直接单击也能选中，走的是同一对动画）

② 拖拽落点：按住一个方块左右拖动 → 两侧方块让出空隙（dragBetweenEnter），移开即合上（dragBetweenLeave）

设置

showPanel：框架从右侧 364px 滑入，550ms，cubic-bezier(0.1, 0.9, 0.2, 1)。

内容不是一起进来的：每个 .win-content 区域各自跑 enterPage （±100px 位移 1000ms + 淡入 170ms），区域之间按官方批次交错 83ms。

所以框架 550ms 就位，内容还在长位移里滑 —— 这就是"标题先、内容随后落定"的层次感。
